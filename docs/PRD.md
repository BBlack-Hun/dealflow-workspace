# dealflow PRD — VC 딜소싱(투자 영업) 관리 도구

> 버전: v1.0 (2026-08-18) · 근거 문서: `docs/DRAFT_REFERENCE.md` (화면 초안 v0.2 + 사용자 피드백 + 자동화 리스트)
> 개발 언어: **Python** · 최우선 목표: **카카오톡 딜소개(딜 안내) 발송 자동화**

---

## 1. 문제 정의

VC 영업(딜소싱) 담당자는 매일 다음 업무를 **수작업**으로 반복한다.

1. IR 기업(스타트업) DB에서 이번에 소개할 기업 2~3개를 고른다.
2. 담당자별 인사문구 + 기업 요약문을 **일일이 복사·조합**해 카카오톡 개인 채팅방마다 붙여넣고 발송한다. (담당자 수십 명 × 주 2회 이상)
3. IR 자료를 요청한 투자사에는 IR 현황·딜소개 문구·보고서와 **IR 자료(딜 IR deck)** 를 해당 채팅방에 일일이 전달한다.
4. 미팅 후 후속(팔로업)을 기억에 의존해 관리하다 누락한다.
5. 담당 투자사 현황은 엑셀 시트로 관리하는데, 가로 스크롤과 필터 부재로 한눈에 파악이 어렵다.

**핵심 페인포인트**: (a) 카톡 발송의 단순 반복노동, (b) 파일 첨부까지 포함한 IR 전달의 번거로움, (c) 후속 알림 누락, (d) 시트 가독성/필터 부재.

## 2. 제품 정의

- **이름**: dealflow — 딜소싱 워크스페이스 (초안 명칭 계승)
- **형태**: 로컬에서 띄우는 Python 웹앱(FastAPI + SQLite) + 사용자 Windows PC에서 도는 **카카오톡 발송 에이전트**(pywinauto)
- **한 줄 정의**: "IR 기업 선택 → 문구 자동 조합 → 카톡 자동 발송 → 반응/IR/미팅/후속을 한 곳에서 관리"

### 핵심 업무 흐름 (초안 계승)

```
IR 기업 DB에서 소개 기업 선택(3개)
  → 오프닝(첫연락/재연락) + 기업 요약문 자동 조합 (담당자별 치환)
  → 카톡 연결된 투자사 담당자 선택 → 미리보기 → 발송 목록 생성
  → [발송 에이전트]가 PC 카카오톡을 구동해 채팅방별 자동 발송 (Day 1)
  → 무응답 시 후속 캐던스 자동 관리: Day 6~7 리마인드 → Day 11~14 미팅 요청
     (응답/IR 요청/미팅 발생 시 시퀀스 자동 중단)
  → 반응 기록 → IR 요청 처리(IR 드라이브 링크 포함 메시지 자동 발송) → 미팅 → 10일 후속 알림
```

**정기 발송 주기(확정)**: 2026년 9월부터 딜소개 회차는 **매월 첫째·셋째 수요일(월 2회)** 진행(기존 매주에서 변경). 주기는 설정 테이블(schedule_rules)로 관리해 추후 변경이 쉽도록 한다.

**규모(확정)**: 운영팀(사용자) **7명**, 투자사 담당자(심사원) 약 **150명**. 초기 데이터는 기존 **구글시트 2개**(투자사/심사원 트래킹, IR 기업현황)를 CSV 임포트로 시딩하고, 이후 서비스에서 CRUD로 관리한다.

## 3. 사용자와 역할

| 역할 | 설명 | 권한 |
|---|---|---|
| **사용자(user)** | VC 영업 담당자. 본인 담당 투자사·딜소개·체크리스트·미팅을 관리 | 본인 데이터 CRUD, 발송 실행 |
| **관리자(admin)** | 팀 리더. 전체 활동 현황 열람 + **마스터 데이터(IR 기업 DB) 편집** | 사용자별 발송 수/메일/IR/미팅/목표 달성률 집계 조회, IR 기업 DB 등 팀 공유 마스터 데이터 편집, 주간 보고 내보내기, 계정 생성·삭제 |

**RBAC 원칙**: 사용자는 **본인 담당 데이터**(내 투자사 담당자, 내 IR 요청·미팅·체크리스트·발송)를 CRUD한다. IR 기업 DB는 팀 공유 마스터 데이터로 전원 조회 가능, 편집은 관리자 + 해당 기업 담당 사용자.

**프라이버시 원칙(확정)**: 관리자는 개인의 업무 체크리스트 원문, 딜소개 발송 원문(인사문구 포함), 개별 채팅 내용을 **볼 수 없다**. 집계 수치만 노출한다.

**계정 정책(확정)**: 휴대폰 번호 기반 로그인(SMS 인증번호). 퇴사 시 관리자가 계정을 삭제하면 개인 데이터(체크리스트, 인사문구, 발송 원문, 담당자 메모 등)는 **하드 삭제**하고, 익명화된 집계 통계만 남긴다. (상세: TECH_SPEC §7)

## 4. 화면 구성 (5 + 1) — 목적 요약

| # | 메뉴 명칭(개선안, FEATURE_SPEC §1 참조) | 초안 코드 | 목적 |
|---|---|---|---|
| 1 | **오늘 할 일** | u-check | 요일 루틴 기반 자동 생성 체크리스트, 완료 기록, 주간 요약 |
| 2 | **IR·미팅 관리** | u-req | IR 자료 요청 트래커(D+N 기한) + 미팅 파이프라인 + [IR 전달] 실행 |
| 3 | **내 투자사** | u-vc | 투자사 담당자(고객) 시트. **PC 한 화면 한 페이지 표시 + 컬럼별 필터 드롭다운** |
| 4 | **딜 기업 DB** | u-su | 소개할 스타트업 DB, 요약문 작성 상태 관리 |
| 5 | **딜소개 보내기** | u-deal | 핵심 화면. 기업 선택 → 문구 조합 → 대상 선택 → 미리보기 → 발송 목록 생성 → 자동 발송 → **후속 시퀀스 관리** |
| 6 | **팀 현황** (관리자) | admin-dash | 사용자별 활동 집계, 주간 보고 내보내기, 마스터 데이터·계정 관리 |

## 5. 자동화 목표 (개발 리스트 6개)

| # | 자동화 | 실현 방법(요약, TECH_SPEC §2 판정표 참조) | 우선순위 |
|---|---|---|---|
| 1 | 카톡 딜소개 자동 발송 (오프닝+요약문 3개 조합, 담당자별 치환) + **Day1→6/7→11/14 후속 캐던스 자동 관리** | **PC 카카오톡 UI 자동화(발송 에이전트)** — 공식 API로는 불가. 후속 예약은 스케줄러, 실행은 사용자 트리거 | **P0 (최우선)** |
| 2 | IR 요청 투자사에 현황·문구·보고서 + **IR 자료 구글 드라이브 링크 포함 메시지 자동 발송** | **PC 카카오톡 UI 자동화(텍스트 전송)** — 파일 첨부 자동화는 하지 않음(확정). IR 자료는 사용자가 드라이브에 올리고 링크를 서비스에 등록 | P0 |
| 3 | 표 항목(컬럼)별 필터 드롭다운 | 웹앱 자체 구현 | P1 |
| 4 | 투자사 관리 시트 PC 한 페이지(가로 스크롤 없음) 표시 | 웹앱 CSS/레이아웃 설계 | P1 |
| 5 | IR 미팅 후 10일 경과 알림 | 발생·스케줄 로직은 설계 완료. **발송 채널(SMS vs 카톡)은 결정 보류** — 채널 어댑터로 추상화, MVP는 앱 내 알림 폴백 | P2 (채널 결정 TODO) |
| 6 | 휴대폰 번호 로그인 + 퇴사 시 계정/데이터 삭제 | SMS 인증(OTP) 자체 구현 | P1 |

## 6. 성공 지표 (MVP 기준)

| 지표 | 현재(수작업) | 목표 |
|---|---|---|
| 딜소개 1회차(담당자 30명) 발송 소요 시간 | 약 60~90분 | **10분 이내** (기업 선택~발송 완료, 발송 중 무인) |
| 발송 성공률 (에이전트 기준) | — | 97% 이상 (실패 건 자동 재시도 1회 + 실패 목록 리포트) |
| IR 전달(드라이브 링크 포함 메시지) 소요 시간 (1건) | 3~5분 | 30초 이내 (버튼 1회) |
| 미팅 후 10일 팔로업 누락률 | 잦음(측정 불가) | 0% (알림 생성·표시율 100%) |
| 딜소개 후속(리마인드·미팅요청) 누락률 | 기억 의존 | 0% (시퀀스 자동 예약·대기 목록 표시) |
| 내 투자사 시트 | 가로 스크롤 필요 | 1280px 이상 PC 화면에서 **가로 스크롤 0** |

## 7. 비범위 (Non-Goals, MVP에서 하지 않는 것)

- 카카오톡 **수신** 메시지 자동 수집/파싱 (반응 기록은 사용자가 수동 입력)
- 이메일 자동 발송 (홍보 메일은 체크리스트 항목으로만 관리)
- 모바일 앱 / 반응형 모바일 최적화 (PC 전용)
- 멀티 테넌트 SaaS / 클라우드 배포 (로컬·사내 단일 서버)
- 무거운 SPA 프레임워크 (React 등) — 서버사이드 렌더링 + 가벼운 JS로 구현
- 알림톡용 카카오 비즈니스 채널 개설 (선택 과제로 로드맵 후순위에만 기재)

| 리스크 | 수준 | 대응 |
|---|---|---|
| **카카오 운영정책상 자동화 프로그램 금지 → 계정 제재 가능성** | **높음(최대 리스크)** | 사람 유사 발송 패턴(랜덤 지연 3~7초), 1회차 발송 상한, 수동 트리거(사용자가 [발송 시작] 클릭 후 지켜봄), 비상 중단 키, 반자동 모드 폴백. 사용자에게 리스크 고지 후 사용 |

| 채팅방 오발송(동명이인 방, 단체방 오매칭) | 중간 | 채팅방 이름 정확 매칭 + 사전 [방 연결 확인] 절차, 발송 전 대상 목록 최종 확인 화면 |
| 드라이브 링크 접근 권한 미설정 → 수신자가 IR 열람 불가 | 낮음 | IR 전달 화면에 "링크 공유 설정(링크가 있는 모든 사용자 보기)" 체크 안내, 링크 미등록 기업은 [IR 전달] 시 경고 |
| 개인정보(휴대폰 번호) 취급 | 낮음 | 로컬 DB, 접근 제어, 퇴사 시 하드 삭제 |
