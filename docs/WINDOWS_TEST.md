# Windows 발송 테스트 가이드

> 개발은 macOS, 실제 운영은 Windows PC. 이 문서는 **Windows 카카오톡 실발송**을
> 검증하는 절차다. (ROADMAP task 1.8 / 1.10)

## 구조 다시 확인

서버(웹앱)와 발송 에이전트는 **분리**되어 있고 HTTP로만 통신한다.
따라서 **서버는 Mac에 그대로 두고, 에이전트만 Windows PC에서 돌리면** 된다.

```
  Mac (개발 PC)                     Windows PC (테스트)
 ┌──────────────────┐              ┌────────────────────┐
 │ 도커 웹앱 :8889   │◀──HTTP 폴링──│ 발송 에이전트        │
 │ DB · 발송 큐      │              │  → 카카오톡 조작     │
 └──────────────────┘              └────────────────────┘
   192.168.0.122                    같은 네트워크(같은 공유기)
```

---

## A. 준비 (Mac 쪽)

1. 웹앱이 떠 있어야 한다.
   ```bash
   cd dealflow && docker compose up -d
   ```
2. 포트가 `0.0.0.0:8889` 로 열려 있는지 확인 (`docker ps`). LAN에서 접근 가능해야 한다.
3. **Mac 방화벽**이 켜져 있으면 8889 인바운드를 허용해야 한다.
   시스템 설정 → 네트워크 → 방화벽 → 옵션.
4. Mac의 LAN IP 확인:
   ```bash
   ipconfig getifaddr en0        # 예: 192.168.0.122
   ```
5. Windows PC 브라우저에서 `http://<MacIP>:8889` 가 열리는지 먼저 확인.
   **안 열리면 그 다음 단계는 의미 없다** — 방화벽/같은 네트워크 여부부터 해결.

> 사무실 네트워크가 분리돼 있어 접근이 안 되면, 서버를 사내 서버/클라우드에 올린 뒤
> 그 주소를 쓰면 된다(배포 스프린트 참고).

---

## B. Windows PC 준비

1. **카카오톡 PC 버전 설치 + 로그인** (테스트할 계정으로)
2. **테스트용 채팅방 준비** — 실제 투자사 방으로 테스트하지 말 것.
   "나와의 채팅" 또는 본인만 있는 방을 쓴다. 방 제목을 정확히 메모해 둔다.
3. **Python 3.10+ 설치** (python.org, 설치 시 "Add to PATH" 체크)
4. 프로젝트 폴더 복사 (USB / 압축 / git 등 무엇이든)
5. 의존성 설치:
   ```bat
   cd dealflow
   python -m venv .venv-agent
   .venv-agent\Scripts\pip install -r requirements-agent-windows.txt
   ```

---

## C. 에이전트 실행

```bat
set DEALFLOW_SENDER=kakao_windows
set DEALFLOW_SERVER_URL=http://192.168.0.122:8889
set DEALFLOW_AGENT_TOKEN=agt_demo_token_sprint1
set DEALFLOW_POLL_INTERVAL=3
.venv-agent\Scripts\python -m agent.main --config agent\config.yaml
```

정상이면 로그에 다음이 찍힌다:
```
agent starting; server=http://192.168.0.122:8889 sender=kakao_windows
using KakaoDesktopSender (Windows)
```
웹 화면 하단 상태바도 **"발송 에이전트 연결됨"** 으로 바뀐다.

---

## D. 발송 테스트

1. Windows 브라우저에서 `http://<MacIP>:8889` 접속
2. **딜소개 보내기** → 기업 선택 → **테스트 방으로 만든 담당자**만 체크
3. 미리보기 확인 → **발송 목록 생성**
4. 카카오톡 창이 자동으로 움직이며 발송된다. **발송 중에는 PC를 건드리지 말 것.**
5. 카톡에 실제로 도착했는지 눈으로 확인

---

## E. 확인해야 할 체크리스트

macOS 실기 검증에서 실제로 걸렸던 항목들이다. Windows에서도 같은 함정이 있을 수 있다.

- [ ] **방 이름 정확 일치** — 시트에서 만든 이름과 실제 카톡방 제목이 같은가?
      (Mac에서 확인된 실제 방: `홍길동 대표님 Deal 공유 우리브이씨 Asset` — 투자사명이 없는 형태도 있음)
- [ ] **Ctrl+V 붙여넣기가 실제로 먹는가?** — macOS에서는 Cmd+V가 **안 먹어서**
      AX value 직접 설정으로 우회했다. Windows에서 안 되면 `_input_text` 검증이
      `input_not_filled` 로 잡아준다(전송은 안 됨).
- [ ] **검색 → Enter 로 방이 열리는가?** — macOS에서는 Enter/AXPress로 안 열려
      **실제 더블클릭**이 필요했다.
- [ ] **오발송 방지 동작** — 일부러 존재하지 않는 방 이름으로 1건 만들어
      `room_mismatch` 로 실패하고 **아무 방에도 안 보내는지** 확인 (가장 중요)
- [ ] **전송 검증** — 발송 후 입력창이 비워지는지(`send_not_confirmed` 안 뜨는지)
- [ ] 여러 건 연속 발송 시 지연(3~7초)이 지켜지는지

## F. 문제 생기면

- 로그: `agent_logs/` 아래 파일과 콘솔 출력
- 실패 사유는 웹 발송 진행 화면의 건별 로그에도 남는다
- 타이밍 문제(창이 늦게 뜸)면 `agent/config.yaml` 의 대기시간을 늘린다
  (`after_open_room`, `after_message_paste` 등 — 코드 수정 불필요)

## G. Windows PC가 없다면

| 방법 | 평가 |
|---|---|
| 팀원의 실제 Windows PC | ✅ **가장 권장** — 실제 운영 환경과 동일 |
| Mac에 Windows VM (Parallels 등) | △ 가능하나 Apple Silicon은 ARM Windows라 카톡(x86) 호환성 이슈 가능 |
| 클라우드 Windows(EC2 등) | ✗ 낯선 IP 로그인으로 카카오 보안 확인이 걸릴 수 있어 비권장 |

당장 Windows가 없으면 **macOS 에이전트(`kakao_mac`)로 기능 검증을 계속하고**,
Windows 검증은 팀원 PC가 확보될 때 이 문서대로 진행하면 된다.
로직(큐·문구·오발송 방지)은 두 센더가 공유하므로 대부분의 버그는 Mac에서 먼저 잡힌다.

## 실기 검증 결과 (2026-08, Windows 11 + 카카오톡 PC)

**결론: 실제 방으로 전송 성공.** 도달 과정에서 세 단계로 막혔고, 각각 원인이 달랐다.

| 증상 | 원인 | 해결 |
|---|---|---|
| `room_mismatch` | 카톡이 포커스를 못 얻은 상태로 Ctrl+F 를 눌러 **브라우저 검색창**에 방 이름이 입력됨. 방은 열리지 않음 | 포커스 확인 후에만 키 입력 (`_focus_verified`) |
| `focus_failed` | Windows 가 백그라운드 프로세스의 `SetForegroundWindow` 를 차단 | `_force_foreground()` — SW_RESTORE + AttachThreadInput + ALT 키 |
| — | — | ✅ 전송 성공 |

### 배운 것

1. **UI 자동화에서 포커스는 안전 문제다.** 포커스 없이 키를 누르면 그 키는 사라지는 게
   아니라 *다른 앱으로 간다*. 확인 없이 진행하면 엉뚱한 곳에 입력되고, 심하면 오발송이 된다.
   → 포커스가 확인되지 않으면 **아무 키도 누르지 않는다**.
2. **`set_focus()` 성공 != 창이 앞에 왔음.** 반드시 포그라운드 창 제목을 다시 읽어 확인한다.
3. **원격 진단이 필요하다.** 사용자 PC 는 접속할 수 없으므로 에이전트가 창 목록·포그라운드
   창·로그를 서버로 올린다(`POST /api/agent/diagnostics` → `data/agent_reports.log`).
   이 데이터가 없었으면 세 단계 모두 추측으로 헤맸을 것이다.

### 운영 시 주의

- 카카오톡을 **최소화하지 말고** 화면에 띄워둘 것
- 발송 중에는 **다른 창을 클릭하지 말 것** (포커스를 뺏으면 그 건이 실패 처리됨)
- 실패해도 오발송은 없다 — 방 제목 정확 일치 검사가 통과해야만 전송된다

# H. 파일 첨부 실기 확인 (자료 전달) — ⚠ **아직 아무도 못 봤다**

> 여기부터는 **확인하러 가는 절차**다. 위(A~G)는 확인이 끝난 문구 발송이고,
> 파일 첨부는 코드만 있고 실기를 한 번도 못 돌렸다.
>
> 개발 기계는 macOS 라 Windows 카카오톡이 아예 없다. 그래서 **확인 창이 뜨는지,
> 뜬다면 무엇이 적혀 있는지 아무도 모른다.** 아래는 그것을 눈으로 보고 오는 순서다.

## H-0. 시작하기 전에 — 지켜야 할 것

- **시험방에서만 한다.** `나에게 보내기`(나와의 채팅) 또는 본인만 있는 방.
  **실투자사 방은 열지도 말 것.** 자료 파일은 한 번 나가면 되돌릴 수 없다.
- 자료 폴더에 **시험용 파일**만 넣는다. 실제 기업 자료를 쓰지 않는다.
  (예: 빈 PDF 하나를 `시험자료.pdf` 로 만들어 둔다)
- 지금 코드는 **꺼져 있다.** 아무것도 안 하면 예전 그대로 문구만 나간다.
  아래 H-1 에서 그 창에서만 켠다.

## H-1. 켜기 (그 창에서만)

```bat
set DEALFLOW_SENDER=kakao_windows
set DEALFLOW_SERVER_URL=http://<서버IP>:8889
set DEALFLOW_AGENT_TOKEN=<웹에서 받은 토큰>
set DEALFLOW_WIN_FILE_SEND=1          ← ★ 이 줄이 파일 첨부를 켠다
.venv-agent\Scripts\python -m agent.main --config agent\config.yaml
```

- `DEALFLOW_WIN_FILE_SEND` 는 **그 검은 창에서만** 산다. 창을 닫으면 다시 꺼진다.
  그래서 시험이 끝난 뒤 실수로 켜진 채 남을 일이 없다.
- 켜지면 켤 때 로그에 `IR 자료 폴더: …` 가 찍힌다. **안 찍히면 안 켜진 것이다.**
- 자료 폴더 자리는 웹에 로그인해 [발송 프로그램] 화면에서 이 PC 의 경로를 넣는다.
  (config 에 적지 않는다 — 발송기를 새로 내려받으면 지워진다)

## H-2. 확인할 것 — **순서대로, 하나씩**

각 항목마다 **무엇을 눌러 무엇을 보면 되는지**를 적었다.
`✅` / `❌` 와 함께 **화면에 뜬 글자를 그대로** 적어 오면 그것으로 코드를 맞춘다.

### ① 파일이 클립보드에 담기는가

발송기를 켜 두고 웹에서 자료가 붙은 건 1건을 시험방으로 보낸다.
발송기가 멈춘 사이(또는 실패한 뒤) **탐색기 빈 자리에서 Ctrl+V** 를 눌러 본다.

- [ ] 파일이 **복사되어 붙는가?**  → 담기고 있다
- [ ] 아무 일도 없다  → 담기지 않았다. 로그에 `clipboard_failed` / `clipboard_mismatch` 가 있는지 본다

> 발송기는 담은 뒤 **다시 읽어 견준다.** 안 담겼으면 붙여넣지 않고 그 자리에서 멈춘다.

### ② 카톡 입력창에 Ctrl+V 가 먹는가

- [ ] 카톡 대화창을 열고 손으로 탐색기에서 파일을 복사 → 대화창에서 Ctrl+V
- [ ] **무엇이 일어나는가?** (셋 중 하나에 표시)
  - [ ] 확인 창이 뜬다 → ③ 으로
  - [ ] 입력창에 첨부 미리보기만 얹힌다(확인 창 없음) → ③ 에 그대로 적는다
  - [ ] 아무 일도 없다 → 붙여넣기가 안 먹는다. **여기서 멈추고 알려 달라**
        (mac 처럼 첨부 단추 → 열기 창으로 길을 바꿔야 한다)

### ③ ★★ 확인 창이 뜨는가, 뜬다면 무엇이 적혀 있는가 ★★  ← **제일 중요**

이 항목이 이번 확인의 전부다. 발송기는 **이 창을 못 찾으면 안 보낸다.**

뜬 창을 보고 아래를 그대로 적어 온다:

- [ ] **창 제목**이 무엇인가?  (예: `파일 전송` / `첨부 확인` / 제목이 없다)
- [ ] **단추 이름**이 무엇인가?  (예: `취소` · `1개 전송` / `아니오` · `보내기`)
- [ ] **개수가 어디에 적혀 있는가?**
      단추에 박혀 있는가(`1개 전송`)? 문장에 있는가(`파일 1개를 …`)? 목록 줄 수뿐인가?
- [ ] **파일명이 보이는가?** 보인다면 **파일명만**인가 **전체 경로**인가?
- [ ] 창 안에 **파일 목록(표)** 이 있는가?

> ⚠ 이 다섯 가지가 코드의 관문이 보는 전부다(방 제목 · 파일명 · 개수).
> 하나라도 못 읽으면 발송기는 **취소하고 안 보낸다.** 그러니 "확인은 됐는데 실패한다"
> 가 정상적인 첫 결과다 — 그때 여기 적어 온 값으로 `agent/selectors.yaml` 의
> `file_send` 를 고치면 통과한다. **코드는 고치지 않는다.**

### ④ 취소가 되는가

- [ ] 확인 창에서 `취소` 를 누르면 **아무것도 안 나가고** 창이 닫히는가?
- [ ] 취소한 뒤 **입력창에 첨부가 남아 있지 않은가?**
      ★ 남아 있으면 **다음에 보내는 문구와 함께 나간다.** 남는다면 반드시 알려 달라
- [ ] Esc 로도 닫히는가?

### ⑤ 한글 파일명 · 공백이 있는 경로

- [ ] 자료 폴더 이름에 **공백**을 넣어 본다 (예: `C:\Users\팀 자료\IR 자료`)
- [ ] 파일명을 **한글 + 공백**으로 만들어 본다 (예: `가나다 회사소개 최종.pdf`)
- [ ] 둘 다 정상으로 붙는가? 확인 창에 이름이 **깨지지 않고** 보이는가?

> 한글 파일명은 자모를 쪼갠 형태와 합친 형태가 있어 눈에는 같은데 글자로는 다르다.
> 견주는 자리는 형태를 맞춰 두었지만(mac 에서 실제로 겪었다), 화면에 **깨져** 보이면
> 그것은 다른 문제다(클립보드가 좁은 글자로 담긴 것) — 그대로 알려 달라.

### ⑥ 보내기 전에 멈출 자리가 있는가

- [ ] 발송 중 **카톡 창을 클릭**해 포커스를 뺏어 본다 → 그 건이 실패로 남는가?
- [ ] 확인 창이 떠 있는 동안 **마우스를 화면 왼쪽 위 구석**으로 던진다
      (pyautogui 안전장치) → 발송기가 멈추는가?
- [ ] 웹 화면의 **[중단]** 을 누르면 다음 건부터 안 나가는가?

### ⑦ 마지막 — 오발송 방지가 그대로 도는가

- [ ] 있지도 않은 방 이름으로 자료 1건을 만들어 본다 → `room_mismatch` 로 실패하고
      **아무 방에도 안 가는가?**
- [ ] 자료 칸에 `../어딘가/무엇` 을 넣어 본다 → **카톡을 열지도 않고** 거절하는가?
      (로그에 `ir_file_rejected`)

## H-3. 확인이 끝나면

1. ③ 에서 적어 온 값으로 `agent/selectors.yaml` 의 `file_send` 를 고친다.
2. `file_send.verified` 를 `true` 로 바꾼다 — 그때부터 서버가 파일이 실린 잡을
   Windows 발송기로 내준다.
3. 판 번호를 올리고(`app/version.py` + `agent/version.py`) 발송기 zip 을 다시 받는다.

> 2 번을 먼저 하면 안 된다. 확인 창 값이 틀린 채로 켜면 **그 회차의 자료 전달이
> 통째로 실패한다** — 자료가 막히면 문구도 안 나간다(그렇게 만들어 두었다.
> "자료 보내드렸습니다" 만 가고 자료가 없는 것이 제일 나쁜 결과라서).

## H-4. 실패 문구 읽는 법

| 로그에 뜨는 말 | 뜻 | 할 일 |
|---|---|---|
| `file_send_unsupported` | 파일 첨부가 **안 켜졌다** | H-1 의 `set DEALFLOW_WIN_FILE_SEND=1` |
| `ir_file_rejected` | 파일명이 규칙에 어긋난다 | 웹의 자료 칸에 **파일명만** 적는다 |
| `이 PC 에 … 없습니다` | 이름은 맞는데 파일이 없다 | 자료 폴더에 파일을 넣는다 |
| `clipboard_failed` | 클립보드를 못 열었다 | 다른 프로그램이 잡고 있다. 다시 시도 |
| `clipboard_mismatch` | 담긴 것이 보내려던 것과 다르다 | ① 로 돌아간다 |
| `confirm_window_not_shown` | **확인 창을 못 찾았다** | ③ 을 적어 와서 selectors 를 고친다 |
| `gate_blocked: …` | 확인 창이 어긋나 **취소했다** | 뒤에 붙은 이유를 그대로 적어 온다 |
| `send_unconfirmed` | 단추는 눌렀는데 창이 안 닫혔다 | **카톡을 직접 확인** — 다시 보내면 겹칠 수 있다 |

> `confirm_window_not_shown` 과 `gate_blocked` 는 **아무것도 안 나간 것**이다.
> `send_unconfirmed` 만 나갔는지 모르는 상태다.

# I. 방 검색 실기 확인 (후보 제목 읽기) — ⚠ **아직 아무도 못 봤다**

발송기 **0.11.0** 부터 Windows 발송기도 카톡 검색 결과에서 **방 제목을 읽어 온다**
(`agent/sender/kakao_windows.py: discover_rooms`). macOS 에만 있던 자리다.

읽는 자리의 컨트롤 경로(`selectors.yaml: room_search`)는 **추측이다** — Windows
카톡의 검색 결과 목록을 UIA 로 들여다본 사람이 없다. H 와 같은 원칙으로 만들었다:

> **못 읽으면 지어내지 않는다.** 컨트롤을 못 찾거나 포커스를 못 잡으면 **후보 0건**
> 으로 답하고 넘어간다. 그리고 [방 연결 확인]은 **확인됨으로 올리지 않는다**
> (`not_found`). 모르는 것을 맞다고 하지 않는다.

**잘못 보낼 위험은 없다.** 이 자리는 방을 **열지도 않고** 글자만 읽는다.

### 0.11.2 — 목록을 못 읽으면 **맨 위 방을 열어** 제목을 읽는다

실기(0.11.1)에서 검색 결과가 화면에 보이는데도 위 컨트롤 경로로는 줄을 하나도
못 읽어 **모든 회사가 후보 0건**이었다. 그래서 목록을 못 읽거나 맞는 줄이 없으면:

1. 검색어가 든 채로 `room_search.open_top_keys`(기본 `["enter"]`)를 눌러 **맨 위
   결과 방을 연다.** Enter 가 첫 줄을 안 열면 `["down", "enter"]` 로 바꾼다.
2. 새로 뜬 카톡 창의 제목(`GetWindowText`)을 읽는다 — 그것이 실제 방 제목이다.
3. 그 창 **하나만** 닫는다(앞에 있으면 Esc, 아니면 WM_CLOSE). 채팅창에는 아무것도
   입력하지 않는다. 그 뒤 메인 창 검색창을 닫는다.
4. 제목에 **회사명이 통째로**(공백·`(주)`·`[딜소개 불가]` 무시) 들어 있을 때만 후보로
   올린다. 새 창이 안 뜨면 0건이다. 끄려면 `room_search.open_top_fallback: false`.

⚠ 방을 한 번 여는 것이라 그 방의 안 읽은 메시지가 **읽음 처리된다.**

실기에서 볼 것:

- [ ] [방 연결 확인] 중 방이 잠깐 열렸다 **바로 닫히는가** (남는 창이 없어야 한다)
- [ ] 메인 카톡 창이 **숨지 않고** 그대로 있는가
- [ ] `agent_logs/agent.log` 에 `맨 위 방 제목을 후보로:` 줄이 뜨는가
- [ ] `agent_logs/kakao_uia_dump.txt`(메인 창)·`kakao_uia_chat_dump.txt`(처음 연
      채팅창)를 보내 준다 — 아래 ② 의 컨트롤 경로를 고칠 근거다. 로그의
      `방 인원 추정: N` 도 함께(아직 판단에 쓰지 않는다)

## I-0. 왜 이게 위험하지 않은지 먼저

- 한 통도 보내지 않는다. `send_text` 를 부르지 않는다.
- 돌려주는 제목은 **검색어의 첫 낱말이 든 줄만** 남는다. 엉뚱한 목록을 읽어도
  남의 방이 후보로 서지 않는다.
- 스타트업 방 맞추기 화면은 후보가 하나뿐이어도 **자동으로 넣지 않는다**
  (`app/services/room_match.py` — 고르는 것은 사람이다).
- ⚠ **투자사 담당자 쪽은 다르다.** 후보가 딱 하나면 서버가 그 제목을
  `kakao_room_name` 에 넣는다(`routers/agent_api._apply_verify_result`, 0.10.0
  이전부터 그랬다). 그래서 아래 ③ 을 **실제 방 이름으로** 한 번은 확인해야 한다.

## I-1. 확인할 것 — 순서대로

### ① 검색창이 열리고 검색어가 **그 칸에** 들어가는가

```
python -m agent.diagnose          # 또는 발송기를 켜 둔 채 [방 연결 확인] 1건
```

- [ ] Ctrl+F 로 검색창이 열리는가? (안 열리면 `selectors.yaml: search_hotkey`)
- [ ] 한글 방 이름이 **깨지지 않고** 들어가는가? (클립보드 + Ctrl+V 로 넣는다)
- [ ] 로그에 `검색어가 검색칸에 들어가지 않았습니다` 가 뜨는가?
      → 되읽기가 엉뚱한 칸을 집은 것이다. `room_search.input_control_type` 을
      `""` 로 비워 되읽기를 끈다(끄더라도 ⑤ 의 '검색어가 든 줄 기다리기' 가 남는다).

### ② ★★ 검색 결과 목록이 **어떤 컨트롤**인가 ★★  ← **제일 중요**

검색어를 넣어 결과가 뜬 상태에서 UIA 로 트리를 떠서 **그대로 적어 온다.**

```python
from pywinauto import Desktop
win = Desktop(backend="uia").window(title_re="카카오톡.*")
win.print_control_identifiers(depth=8)   # ← 출력을 전부 붙여 온다
```

적어 올 것:

- [ ] 결과 목록을 담은 컨트롤의 **control_type** (`List`? `Tree`? `DataGrid`?)
- [ ] 그 컨트롤의 **AutomationId** (있으면 `room_search.list_auto_id` 에 적어
      목록을 좁힌다 — 전체 대화목록과 구분된다면 꼭 적는다)
- [ ] 한 줄의 **control_type** (`ListItem`? `TreeItem`?)
- [ ] ★ 방 제목이 **어디에** 적히는가
      - 줄 안의 첫 `Text` 조각이면 → 지금 값 그대로 (`item_text_control_type: "Text"`)
      - **줄 이름(Name) 자체**가 제목이면 → `item_text_control_type: ""` 로 비운다
      - 줄 이름이 `제목 + 마지막 메시지 + 시각` 으로 **붙어** 나오면 → 그 모양을
        그대로 적어 온다. 붙은 글자에서 제목만 잘라내는 일은 짐작이라 코드가
        혼자 하지 않는다.

### ③ 읽어 온 제목이 **진짜 방 제목과 글자까지 같은가**

- [ ] 방 이름에 **공백이 여럿**인 방(`회사 명`)을 하나 골라 확인한다 —
      연속 공백만 줄여서 견준다(그 밖의 보정은 하지 않는다)
- [ ] 제목이 긴 방이 **잘려서** 오지 않는가? (`…` 로 줄면 그 모양을 적어 온다)
- [ ] [방 연결 확인]에서 **있는 방**이 `확인됨`, **없는 방**이 `못 찾음` 으로
      갈리는가? → 0.11.0 전에는 **둘 다 `확인됨`** 이었다. 그것이 이 판의 핵심이다

### ④ 같은 이름의 방이 둘이면 **고르지 않는가**

- [ ] 같은 제목의 방을 일부러 둘 만들고 확인 → `ambiguous`(같은 이름의 방이
      여러 개입니다)로 뜨는가? 하나를 골라 버리면 안 된다

### ⑤ 결과가 **한 박자 늦게** 반영되는 것을 잡는가

- [ ] 서로 다른 두 이름을 **연달아** 확인한다 → 두 번째 결과에 첫 번째 방이
      섞여 들어오지 않는가? (느리면 `timings.room_search_wait` 를 늘린다)

### ⑥ 후보가 스타트업 방 맞추기 화면까지 올라오는가

- [ ] `/deals/startup-ir` 의 방 맞추기에서 [카톡에서 찾기] → 후보가 서는가?
- [ ] 발송기 설정에 `room_marker` 가 **비어 있는가?** 들어 있으면 그 글자가 든
      방만 남아 스타트업 방이 전부 걸러진다

## I-2. 확인이 끝나면

1. ② 에서 적어 온 값으로 `agent/selectors.yaml` 의 `room_search` 를 고친다.
   **코드는 고치지 않는다**(ROADMAP 공통 원칙 2).
2. 판 번호를 올리고(`app/version.py` + `agent/version.py`) zip 을 다시 받는다.
3. 이 문서의 "⚠ 아직 아무도 못 봤다" 를 지우고 본 값을 적는다.

## I-3. 로그 읽는 법

| 로그에 뜨는 말 | 뜻 | 할 일 |
|---|---|---|
| `카톡 포커스 실패` | 카톡이 앞으로 안 나왔다 | 최소화하지 말고 띄워 둔다 |
| `검색어가 검색칸에 들어가지 않았습니다` | 되읽기가 어긋났다 | ① 의 마지막 줄 |
| `검색 결과 목록을 읽지 못했습니다` | **컨트롤을 못 찾았다** | ② 를 적어 와서 selectors 를 고친다 |
| `room_search 셀렉터가 비어…` | selectors 가 비었다 | `room_search` 를 되살린다 |
| `검색 결과에 … 가 든 줄이 없습니다` | 읽었는데 그 이름이 없다 | 카톡에서 사람이 직접 본다 |

> 위의 **어느 것도 '보냈다/안 보냈다' 와 무관하다.** 이 자리는 한 통도 보내지
> 않는다. 전부 `후보 0건` 또는 `못 찾음` 으로 끝난다.
