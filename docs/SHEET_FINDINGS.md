# 실제 구글시트 분석 결과 (Sprint 2 임포트 설계 근거)

> 2026-08-19 실 시트 직접 파싱. 이 문서는 기획서(fable5 산출물)를 보완하는 **관측 기록**이다.
> Sprint 2 `scripts/import_sheets.py` 는 반드시 이 구조를 근거로 작성한다.

## 1. 투자사 관리 시트는 **사용자(영업담당) 1명당 1개**

운영팀 7명이 각자 자기 시트를 가진다. 따라서 임포트는 **"시트 1개 = 사용자 1명"** 매핑이며,
`vc_contacts.user_id` 로 소유자를 구분한다(현재 모델 구조가 이에 부합).

- 분석한 시트: 담당자 **126행** (사용자가 말한 "약 150명" 규모와 일치)
- 임포트 CLI는 `--user-id`(또는 `--user-phone`) 인자를 필수로 받아야 한다.

## 2. 컬럼 구조 (헤더는 **2행**, 데이터는 4행부터)

1행은 제목/메모용이라 헤더가 아니다. 파서는 헤더 행 인덱스를 하드코딩하지 말고
"그룹/이름/투자사명"이 모두 등장하는 행을 헤더로 탐지하는 편이 안전하다.

| idx | 컬럼 | 비고 |
|---|---|---|
| 0 | (번호) | 순번 |
| 1 | 그룹 | 대부분 공란 |
| 2 | **이름** | `홍길동 대표님` — **이름+직함이 한 셀에 합쳐져 있음** → 분리 파싱 필요 |
| 3 | 투자사명 | `가나벤처스` |
| 4 | **초대완료여부** | `완료` 등 — **현재 모델에 없는 필드. 추가 필요** (카톡방 초대 여부) |
| 5 | 투자분야/라운드사이즈 | **대부분 공란**, 있어도 자유 서술(`8/19 : 초기 기업보다는 성장단계 기업들 위주로 검토`) |
| 6~8 | 8월: 1차 딜소개 / IR 자료 요청 기업 / 미팅 요청·안내전화·미팅완료 | 3열 세트 |
| 9~11 | 7월: 위와 동일 3열 | |
| 12~14 | 6월: 위와 동일 3열 | |

### ★ 월별 3열 세트가 계속 오른쪽으로 늘어나는 구조
시트는 달이 갈수록 열이 무한히 늘어난다(6·7·8월…). 이것이 시트의 구조적 한계이고,
**서비스가 시트보다 나은 핵심 지점**이다 → DB에서는 `contact_activities` **행**으로 정규화한다.
임포트 파서는 3열 세트를 **반복 스캔**해 (월, 유형, 내용) 레코드로 펼쳐야 한다.

### 셀 값 형태 (1차 딜소개)
```
8/4(화) 핵심 딜 8개사

8/13(목) 샘플기업A, 샘플기업B, 샘플기업C
8/19(수) 샘플기업D, 샘플기업E, 샘플기업F, 샘플기업G, 샘플기업H
```
→ 한 셀에 **여러 회차**가 줄바꿈으로 누적. `날짜 + 기업목록` 으로 파싱해 회차별 레코드화.

## 3. 확인된 사실들

- **9월부터 월 2회**: 시트 헤더에 `첫째주 수요일 투자사 5개, 기업 20개 / 셋째주 …` 문구 존재 →
  "매월 첫째·셋째 수요일" 확정 근거와 일치.
- **1회 발송 기업 수는 3개가 아니다**: `핵심 딜 8개사`, 실제 스크립트는 `핵심 딜 7개사`.
  → 코드의 기업 3개 상한은 제거함(`MAX_COMPANIES_PER_SEND = 10`).
- **투자성향 데이터는 대부분 비어 있다** → 매칭은 정보 없음을 '부적합'이 아니라
  **UNKNOWN(판단 불가)** 으로 처리해야 한다(현재 `matcher.py` 가 그렇게 동작).

### 재임포트 시 지키는 것 (구현 결정)

- **방 이름은 비어 있을 때만 자동 생성**한다. 사용자가 실제 카톡 제목에 맞춰 고친 값을
  임포트가 되돌리면 그 담당자 발송이 통째로 skip 된다.
- 시트의 **빈 칸으로 기존 값을 지우지 않는다**(빈 값은 '모름'이지 '지워라'가 아니다).
- 투자분야 칸은 대부분 자유 서술이라 **짧은 태그 나열일 때만** `sectors` 로 분해한다.
  잘못된 태그는 발송 전 성향 경고(`matcher`)를 오염시킨다.
