# dealflow FEATURE_SPEC — 화면·자동화 상세 기획

> 버전: v1.0 (2026-08-18) · 상위 문서: `docs/PRD.md` · 데이터 정의: `docs/DATA_MODEL.md`
> 초안 v0.2 화면 구조를 계승하고, 사용자 피드백 4건(메뉴 명칭 / 폰트 통일 / 한 페이지 표 / 필터 드롭다운)을 반영한다.

## 0. 공통 UI 규칙

### 0.1 본문 폰트 통일 (피드백 #2 — 필수)

- 화면의 **모든 본문 텍스트는 Pretendard 1종으로 통일**한다. 초안에서 혼용된 폰트(고정폭·세리프 등)를 제거한다.
- 적용 방법: Pretendard Variable(woff2)을 `static/fonts/`에 **로컬 번들**(오프라인 동작 보장)하고 전역 지정한다.

```css
@font-face {
  font-family: "Pretendard Variable";
  src: url("/static/fonts/PretendardVariable.woff2") format("woff2-variations");
  font-weight: 45 920; font-display: swap;
}
:root { --font-body: "Pretendard Variable", Pretendard, "Malgun Gothic",
        -apple-system, "Apple SD Gothic Neo", sans-serif; }
body, button, input, select, textarea, table { font-family: var(--font-body); }
```

- 숫자 컬럼(금액·건수)은 별도 폰트를 쓰지 않고 `font-variant-numeric: tabular-nums`로 정렬감만 준다.
- **카톡 발송 미리보기 영역도 동일 폰트**를 사용한다(발송 문구는 어차피 plain text).

### 0.2 좌측 메뉴 명칭 개선 (피드백 #1 — 필수)

실무 어휘 기준 개선안. **권장안을 기본 채택**하고, 대안은 팀 검토용으로 남긴다.

| 초안 명칭 | **권장안 (채택)** | 대안 | 개선 이유 |
|---|---|---|---|
| 업무 체크리스트 | **오늘 할 일** | 데일리 루틴 | "체크리스트"는 수단, 실제 업무는 "오늘 처리할 일" |
| IR 요청·미팅 | **IR·미팅 관리** | 파이프라인 | 요청 트래킹+미팅 조율을 한 단어 흐름으로 |
| 내 투자사 | **내 투자사** (유지) | 투자사 담당자 | 실무에서 "내 하우스/내 투자사"로 부름. 유지가 자연스러움 |
| IR 기업 DB | **딜 기업 DB** | 소개 기업 풀 | 소개(딜)할 기업이라는 목적이 드러나게 |
| 딜소개 발송 | **딜소개 보내기** | 카톡 딜소개 | 동사형이 실제 행동(보낸다)과 일치 |
| (관리자) 전체 현황 | **팀 현황** | 전체 현황 | "전체"보다 집계 대상(팀)이 명확 |

메뉴 순서(사용 빈도순): 오늘 할 일 → 딜소개 보내기 → IR·미팅 관리 → 내 투자사 → 딜 기업 DB → (admin만) 팀 현황.
좌측 메뉴 하단에 **에이전트 상태 배지**(TECH_SPEC §4) 상시 표시: `● 발송 에이전트 연결됨 / ○ 오프라인`.

### 0.3 레이아웃 기준

- 대상 해상도: **PC 1280px 이상** (권장 1440/1920). 모바일 비대응(비범위).
- 구조: 좌측 고정 사이드바(200px) + 본문. 본문 최대폭 제한 없음(표 화면은 전체폭 사용).
- 상태 배지 색: 성공/활발=green, 대기/조율중=amber, 실패/반응없음=red, 중립=gray.

## 1. 화면 1 — 오늘 할 일 (u-check)

**목적**: 요일 루틴 기반으로 오늘 할 일이 자동 생성되고, 완료 체크만 하면 주간 실적이 쌓인다.

### 유저플로우
```
접속 → 오늘 날짜의 체크리스트 자동 생성(요일 루틴 매칭, 최초 접속 시 1회)
 → 항목 체크 [완료] → 완료 시각·건수 입력(건수형 항목만)
 → 상단 '이번 주 요약' 자동 갱신
```

### 화면 구성
- **상단 요약 카드 4개**: 이번 주 딜소개 발송 N건 / 홍보 메일 N건 / 신규 연결 N명 / IR 전달 N건.
- **오늘 목록**: 체크박스 / 항목명 / 유형 배지(발송·메일·전화·미팅·IR) / 완료 시각 / 건수 입력란 / 메모.
- **루틴 관리(접이식 하단 패널)**: 항목명, 반복 요일(월~일 다중), 유형, 활성 여부. 예: "딜소개+리마인드 카톡 — 화·목".
- 딜소개/IR 유형 항목에는 해당 화면 바로가기 버튼(→ 딜소개 보내기, → IR·미팅 관리).

### 입출력
- 입력: 체크/해제, 건수, 메모, 루틴 CRUD.
- 출력: `checklist_items` 생성·갱신, 주간 집계(팀 현황·주간 요약의 원천).

### 엣지케이스
| 케이스 | 처리 |
|---|---|
| 주말/휴일에 루틴 없음 | "오늘 예정된 루틴이 없습니다" + 수동 항목 추가 버튼 |
| 어제 미완료 항목 | 오늘 목록 상단에 "밀린 일" 섹션으로 이월 표시(자동 완료 처리 안 함) |
| 루틴을 삭제해도 | 과거 생성된 항목·집계는 보존(루틴만 비활성) |
| 자정 넘겨 작업 | 완료 시각은 실제 시각 저장, 귀속 날짜는 항목의 생성 날짜 유지 |

## 2. 화면 2 — IR·미팅 관리 (u-req)

**목적**: IR 자료 요청을 기한(D+N)으로 추적하고, [IR 전달] 버튼 한 번으로 카톡방에 **IR 드라이브 링크가 포함된 안내 메시지**를 자동 전송한다. 미팅 파이프라인과 10일 후속 알림을 함께 관리.

> **확정**: 카톡 파일 첨부 자동화는 하지 않는다. IR 자료는 사용자가 **구글 드라이브에 수기 업로드** 후 링크를 딜 기업 DB에 등록하고, 자동 발송 메시지 **본문에 링크 텍스트를 포함**해 전송한다. (에이전트는 텍스트 전송만 수행 → 안정성 ↑)

### 유저플로우 A — IR 요청 처리 (자동화 #2 연동)
```
투자사 담당자가 카톡으로 IR 요청 → 사용자가 [IR 요청 추가] (담당자·기업 선택, 기한 D+3 기본)
 → 목록에 '미전달' 상태로 표시(D-day 카운트다운, 지연 시 red)
 → [IR 전달] 클릭 → 전달 내용 구성 모달:
     ① 안내 문구(자동 생성: IR 현황 + 딜소개 문구 + 보고서 요약, 수정 가능)
     ② IR 드라이브 링크 자동 삽입(기업의 ir_drive_url — 미등록 시 등록 유도)
     ③ 대상 카톡방 확인(담당자의 연결된 방 이름)
 → [발송 큐에 추가] → 발송 에이전트가 링크 포함 메시지를 텍스트 전송 (TECH_SPEC §5)
 → 성공 시 상태 '전달완료' + 전달 시각 자동 기록
```

전달 메시지 템플릿(기본, 수정 가능):
```
{이름} {직함}님, 요청 주신 {기업명} IR 자료 전달드립니다.
{한줄 소개 / 투자유치상태 요약}
IR 자료: {ir_drive_url}
검토 후 미팅 원하시면 편하신 일정 몇 가지 말씀 부탁드립니다.
```

### 유저플로우 B — 미팅 파이프라인
```
IR 전달 후 반응 오면 [미팅 생성] → 상태: 조율중 → 일정확정 → 완료 / Drop
 → '완료' 전환 시 완료일 기록 → 스케줄러가 완료일+10일에 후속 알림 생성 (자동화 #5,
   발송 채널은 결정 보류 — MVP는 앱 내 알림·오늘 할 일 표시)
```

### 화면 구성
- **IR 요청 표**: 요청일 / 투자사·담당자 / 요청 기업 / 기한(D+N, 남은 일수 배지) / 상태(미전달·전달완료) / [IR 전달] 버튼.
- **미팅 파이프라인 표**: 대상 기업 / 투자사·담당자 / 경과일 / 상태(조율중·일정확정·완료·Drop) / 다음 액션 메모 / 미팅일 / 후속 알림 상태(예정일·발송됨).
- 두 표 모두 컬럼 필터 드롭다운 적용(§8 공통 명세).

### 입출력
- 입력: IR 요청 CRUD, 전달 문구 수정, 미팅 상태 전환, 다음 액션 메모.
- 출력: `ir_requests` 상태 전이, `send_jobs`(kind=ir_delivery) 생성, `meetings` 생성·전이, `notifications`(D+10) 예약.

### 엣지케이스
| 케이스 | 처리 |
|---|---|
| 담당자에게 연결된 카톡방 이름 미등록 | [IR 전달] 비활성 + "내 투자사에서 카톡방 이름을 먼저 등록하세요" 링크 |
| 기업의 IR 드라이브 링크 미등록 | 모달에서 경고 + 링크 입력란 즉석 제공(저장 시 기업 DB에도 반영), 링크 없이 문구만 전송도 선택 가능 |
| 드라이브 링크 공유 권한 미설정 우려 | 모달에 "링크가 있는 모든 사용자 보기 권한인지 확인" 안내 문구 상시 표시 |
| 발송 실패(에이전트) | 상태 '미전달' 유지 + 실패 사유 표시 + [재시도] |
| 미팅 '완료' 후 10일 내 Drop/재미팅 | 상태 변경 시 예약된 D+10 알림 자동 취소 |
| 기한 초과 | 행 강조(red) + 오늘 할 일에 "지연 IR N건" 자동 표시 |

## 3. 화면 3 — 내 투자사 (u-vc)

**목적**: 담당 투자사 담당자(=고객) 시트를 **PC 한 화면에 가로 스크롤 없이** 보여주고(피드백 #3), **컬럼별 필터 드롭다운**(피드백 #4)으로 즉시 좁혀본다. 딜소개 발송의 대상 원천.

### 한 페이지 표시 설계 (피드백 #3 — 필수 요구: 가로 스크롤 0)

1280px 기준 **7컬럼 고정 레이아웃**. 셀 안에서 2줄 스택으로 정보를 합쳐 컬럼 수를 줄인다.

| 컬럼 | 폭 | 내용(스택 구성) |
|---|---|---|
| 담당자 / 투자사 | 16% | 1줄: 담당자명 · 직함 / 2줄: 투자사명 · 그룹(회색 소자) |
| 채널 | 8% | 아이콘 배지: 💬카톡 ✉메일 (연결된 것만, 카톡은 방 연결 여부 ●/○) |
| 투자 성격 | 16% | 1줄: 단계 태그(Seed·A·B·Pre-IPO) / 2줄: 섹터 태그(최대 3개, 초과 시 +N) |
| 최근 딜소개 | 12% | 날짜(MM.DD) + 회차명, 툴팁에 기업 목록 |
| 반응 | 12% | IR 요청 N · 미팅 N (최근 90일) |
| 상태 | 10% | 활발 / 반응없음 / 검토중단 배지 |
| 메모 / 액션 | 26% | 1줄 말줄임 메모(클릭 시 팝오버 전체보기) + [딜소개] [IR] 바로가기 |

- `table-layout: fixed; width: 100%` + 셀 `text-overflow: ellipsis` + hover 툴팁 → **어떤 데이터에서도 가로 스크롤이 생기지 않음을 보장**.
- 세부 정보(전화번호, 이메일 전문, 카톡방 이름, 전체 이력)는 행 클릭 → **우측 슬라이드 상세 패널**에서 확인·수정. 표에는 요약만.
- 밀도 토글(기본 보통 / 촘촘) 제공 — 촘촘 모드에서 행높이 축소로 40행+ 한 화면.

### 필터 드롭다운 (피드백 #4 — §8 공통 명세 적용)

- 필터 대상 컬럼: 채널(카톡 연결/메일만), 투자 단계, 섹터, 상태, 최근 딜소개(7일 내/30일 내/없음), 반응(IR 있음/미팅 있음/반응 없음).
- 초안의 프리셋 탭(전체/카톡 연결/메일만/반응 없음)은 **빠른 필터 칩**으로 유지하되 내부적으로 드롭다운 필터 조합으로 동작.

### 유저플로우
```
목록 조회 → 필터 칩/드롭다운으로 좁힘 → 행 클릭 → 상세 패널에서 수정
 → [담당자 추가] 모달(그룹·이름·직함·투자사·채널·카톡방 이름·투자분야/라운드 사이즈)
 → [카톡방 연결 확인]: 에이전트에 방 이름 검색을 요청해 존재 여부 검증(TECH_SPEC §5.4)
```

### 초기 데이터 임포트 (구글시트 A — 투자사/심사원 트래킹)
- 시트 A 컬럼 매핑: 번호→(무시), 그룹→group_name, 이름("홍길동 대표님")→name+title 분리 파싱, 투자사명→firm, 투자분야/라운드사이즈→sectors·round_size, 1차 딜소개(날짜+딜 개수)/IR 자료 요청(기업명 리스트)/미팅 요청/월별(6·7·8월) 활동 → **contact_activities**(과거 이력 보존용, DATA_MODEL §2.5).
- [시트 임포트] 버튼(관리자 또는 본인 담당분): CSV 업로드 → 매핑 미리보기 → 임포트. 헤더에 섞인 임시 로그인 문자열 등 비정형 행은 무시(결과 리포트에 스킵 목록 표기).
- 상세 패널에 "활동 이력" 탭: 임포트된 월별 기록 + 서비스에서 자동 쌓이는 발송/IR/미팅 이력 통합 타임라인.

### 입출력
- 입력: 담당자 CRUD(본인 담당분), 카톡방 이름 등록·검증, 상태 변경, 메모, CSV 임포트.
- 출력: `vc_contacts`·`contact_activities` 갱신. "최근 딜소개/반응"은 `send_items`·`ir_requests`·`meetings`에서 자동 집계(수기 입력 아님).

### 엣지케이스
| 케이스 | 처리 |
|---|---|
| 카톡방 이름이 실제 카톡과 불일치 | [방 연결 확인] 실패 표시(○ 배지), 발송 대상 선택 시 경고 |
| 동일 이름 방 복수 존재 | 검증 시 "복수 매칭" 경고 → 방 이름을 고유하게 바꾸도록 안내(카톡에서 방 이름 편집) |
| 담당자 이직/투자사 변경 | 이력 보존 위해 삭제 대신 '검토중단' + 새 레코드 권장(도움말 문구) |
| 1600px 이상 광폭 모니터 | 컬럼 % 폭 그대로 확장(여백 낭비 없음) |

## 4. 화면 4 — 딜 기업 DB (u-su)

**목적**: 소개할 스타트업 정보와 **딜 요약문**(발송 문구의 재료)·**IR 드라이브 링크**를 관리하는 팀 공유 마스터 데이터. 기존 구글시트 [IR 기업현황]을 임포트해 시딩한다.

### 필드 (구글시트 B 헤더 계승 — DATA_MODEL §2.5)
`NO, 기업명, 사업분야 대분류, 소분류, 기업구분(시리즈), 한줄 소개, 담당자, IR deck유무, 계약여부, 계약 월 기입, 핵심/TOP Deal, 투자유치상태, 비고` + 서비스 추가 필드: 딜 요약문, IR 드라이브 링크(ir_drive_url), 최근 매출·누적 투자·유치 희망·Pre Value.

### 화면 구성
- 표 컬럼(요약): 기업명(핵심/TOP ★배지) / 대분류·소분류 / 시리즈 / 한줄 소개(말줄임) / 담당자 / IR 링크(🔗 유무) / 계약여부 / 투자유치상태 / 요약문 상태.
- 필터 드롭다운: 대분류, 소분류, 시리즈, 담당자, IR 링크 유무, 계약여부, 투자유치상태, 핵심/TOP, 요약문 상태. (초안 프리셋: 전체/딜소개 가능/요약문 미작성/정보 부족 → 빠른 필터 칩 유지)
- 행 클릭 → 상세 패널: 기본 정보 폼(시트 B 전 필드 + 매출/투자 금액) + **딜 요약문 편집기**(발송에 그대로 들어가는 텍스트, 글자수 카운터) + **IR 드라이브 링크 입력란**(URL 검증, [링크 열기] 버튼, 공유 권한 확인 안내).
- "딜소개 가능" 조건 자동 판정: 요약문 작성완료 AND 필수 필드(기업명·대분류·시리즈) 채움.
- [시트 임포트] 버튼(관리자): CSV 업로드 → 컬럼 매핑 미리보기 → 중복(기업명) 병합 정책 선택 → 임포트 결과 리포트.

### 권한 (RBAC)
- 조회: 전원. 편집: **관리자 + 해당 기업 담당자(담당자 필드의 사용자)**. 생성: 전원(생성자가 담당자 기본값).

### 입출력
- 입력: 기업 CRUD, 요약문 텍스트, IR 드라이브 링크, CSV 임포트.
- 출력: `ir_companies`. 딜소개 보내기 화면의 기업 선택 목록·IR 전달 링크의 원천.

### 엣지케이스
| 케이스 | 처리 |
|---|---|
| 요약문 미작성 기업을 발송에 선택 시도 | 선택 불가(비활성) + "요약문을 먼저 작성하세요" |
| 요약문에 치환 변수 오타(`{담당자님}` 등) | 저장 시 허용 변수 목록 외 `{}` 패턴 경고 |
| 드라이브 링크가 drive.google.com 형식이 아님 | 저장 시 경고(차단은 안 함 — 타 클라우드 허용) |
| 임포트 CSV에 헤더 불일치/빈 행 | 매핑 화면에서 무시 컬럼 지정, 빈 행 스킵 + 결과 리포트에 표기 |
| 금액 입력 | 억 원 단위 숫자 입력, 표시는 "30.9억" 자동 포맷 |

## 5. 화면 5 — 딜소개 보내기 (u-deal) ★핵심

**목적**: 이번 회차 기업 3개를 골라 인사문구+요약문을 자동 조합하고, 대상 담당자별로 치환된 메시지를 미리보고, 발송 목록을 만들어 **발송 에이전트로 자동 발송**한다. 발송 후에는 담당자별로 **다단계 후속 캐던스(시퀀스)** 가 자동 관리된다. (자동화 #1)

### 발송 캐던스 (실제 딜소개 스크립트 기준 — 핵심 확장)

딜소개는 단발 발송이 아니라 **응답이 올 때까지의 3단계 시퀀스**다.

| 단계 | 시점(기본값, 조정 가능) | 내용 |
|---|---|---|
| **Day 1 — 딜소개** | 발송일 | 오프닝(첫연락/재연락 2버전) + 기업 3개 요약 + 클로징 "관심 가시는 기업 있으시면 IR Deck 공유드리겠습니다" |
| **Day 6~7 — 리마인드** | +6일(6~7 창에서 랜덤) | "검토 중 궁금하신 점 있으시면 말씀 부탁드립니다" |
| **Day 11~14 — 미팅 요청** | +11일(11~14 창에서 랜덤) | "다음주 또는 다다음주 20~30분 정도 간단히 미팅 가능하실지" |

**중단 규칙**: 담당자가 중간에 응답하면 시퀀스 중단. 트리거는 ① 사용자가 시퀀스에 [응답 옴] 기록, ② 해당 담당자로 IR 요청 생성, ③ 미팅 생성 — 셋 중 하나면 남은 단계 자동 취소. 미응답 시 다음 단계가 자동 예약된다.

**실행 방식(감독 모드 유지)**: 스케줄러가 매일 09:00 도래한 후속 건을 모아 "오늘 예정 후속 N건" 발송 대기 목록을 만들고, 오늘 할 일에 항목을 자동 추가한다. **실제 카톡 발송은 사용자가 [후속 발송 시작]을 눌러 일괄 실행**(무인 발송 금지 원칙 유지, TECH_SPEC §8). 주말·공휴일 도래분은 다음 영업일로 이월.

**정기 회차 주기(확정, 2026년 9월부터)**: 신규 딜소개 회차는 **매월 첫째·셋째 수요일(월 2회)** 진행. 스케줄러가 해당일 아침에 회차 초안(deal_batch)을 자동 생성하고 오늘 할 일에 "딜소개 회차 준비" 항목을 추가한다(기업 선택·발송은 사용자가 진행). 각 회차 발송일(D0=수요일) 기준으로 위 캐던스(D+6~7, D+11~14)가 예약된다. 주기 규칙은 하드코딩하지 않고 **설정 테이블(schedule_rules)** 로 관리해 추후 변경(예: 주 1회 복귀)이 쉬워야 하며, 과거 '매주' 진행 이력과 혼재를 위해 회차에 발송일·주기유형 필드를 둔다(DATA_MODEL §2.7).

> 이 시퀀스는 자동화 #5 '미팅 후 10일 알림'(미팅 이후 팔로업)과 **별개**인 '응답 전 후속 시퀀스'다. 스케줄러가 둘 다 관리한다.

### 유저플로우
```
① 회차 만들기: [새 회차] → 회차명 자동(예: "8월 3주차") 
② 기업 선택: 딜 기업 DB 중 '딜소개 가능' 기업에서 3개 선택(1~3개 허용, 기본 3)
③ 문구 구성: 내 인사문구(사용자별 저장, 복수 보유 중 선택) + 기업 요약문 3개 자동 조합
   - 치환 변수: {이름} {직함} {투자사} — 담당자별 자동 치환
   - 조합 결과를 인라인 수정 가능(회차 단위 오버라이드)
④ 대상 선택: 카톡방 연결(●) 담당자 목록에서 체크(전체선택/필터 연동)
   - ⚠ 성격 불일치 경고: 담당자 투자 단계 태그와 선택 기업 단계가 어긋나면
     행에 경고 배지(예: "Seed 전문 담당자 ← Pre-IPO 딜 포함") — 발송은 막지 않음
⑤ 미리보기: 카톡 말풍선 스타일로 담당자별 최종 문안 확인(좌: 대상 목록, 우: 미리보기)
⑥ [발송 목록 생성] → 대상 N명 요약 확인 모달(방 이름 목록 포함) → [발송 시작]
⑦ 발송 진행 화면: 실시간 진행 (대기 n / 발송중 / 성공 n / 실패 n), 건별 로그
   - [일시정지] [중단] 버튼, 에이전트 오프라인이면 "큐 대기 중" 표시
⑧ 완료: 결과 요약 + 실패 건 [재시도] + 오늘 할 일 '딜소개' 항목 자동 완료 체크
⑨ 시퀀스 시작: 성공 발송된 담당자마다 후속 시퀀스 자동 생성(Day6~7·Day11~14 예약)
   → 하단 '진행 중 시퀀스' 표에서 담당자별 현재 단계·다음 예약일·[응답 옴] [중단] 관리
```

### 화면 구성 (3단 위저드형 단일 페이지)
- 좌: 회차 정보 + 기업 선택 카드 3슬롯.
- 중: 문구 편집(인사문구 선택 드롭다운 + 조합 결과 편집기, **Pretendard 단일 폰트**).
- 우: 대상 담당자 체크 목록(검색·필터) + 카톡 미리보기 + [발송 목록 생성].
- 하단 탭 2개:
  - **최근 회차**: 회차명·발송일·주기유형(정기/수시)·대상 수·성공/실패·[결과 보기].
  - **진행 중 시퀀스**: 담당자 / 회차(기업 세트) / 현재 단계(Day1·리마인드·미팅요청) / 다음 예약일 / 상태(진행중·응답옴·IR요청·미팅전환·완료·중단) / [응답 옴] [중단] 버튼. 오늘 도래 건은 상단 고정 + [후속 발송 시작] 일괄 버튼.

### 메시지 조합 규칙 (실제 스크립트 구조 반영)

```
{오프닝}          ← 첫연락/재연락 2버전 중 자동 선택(해당 담당자 발송 이력 유무),
                    사용자별 개인화 저장. 치환: {담당자명} {직함} {투자사}
                    예(첫연락): "안녕하세요 {담당자명} {직함}님, 카톡으로 스타트업
                    딜소개를 드리고 있는데 검토해보시면 좋을 기업들 공유드립니다."
                                (빈 줄)
[1] {기업A 요약}   ← IR 기업 DB 필드에서 자동 생성(아래 포맷)
                                (빈 줄)
[2] {기업B 요약}
                                (빈 줄)
[3] {기업C 요약}
                                (빈 줄)
{클로징}          ← 단계별 기본 문구:
                    Day1  "관심 가시는 기업 있으시면 IR Deck 공유드리겠습니다."
                    리마인드 "검토 중 궁금하신 점 있으시면 말씀 부탁드립니다."
                    미팅요청 "다음주 또는 다다음주 20~30분 정도 간단히 미팅 가능하실지요?"
```

**기업 요약 자동 생성 포맷** (구분자 `|`, IR 기업 DB 필드에서 조합 — 사용자는 인사문구만 개인화하면 됨):
```
[{사업분야}] | {한줄 소개(핵심기술/사업)} | 매출 {매출}억 | 누적투자금액 {누적투자}억
 | {유치희망}억 투자유치중 | Pre Value 약 {PreValue}억원 | {경쟁력}
예: [애그테크] | B2B 농산물 선도거래 'Presell' | 매출 30억 | 누적투자금액 5.6억
 | 20억 투자유치중 | Pre Value 약 210억원 | 상급 유통사 12곳 계약
```
- 값이 비어 있는 항목은 해당 세그먼트를 **통째로 생략**(빈 "매출 억" 방지).
- 자동 생성 결과는 기업 상세의 `딜 요약문`에 캐시되며 사용자가 수동 다듬기 가능(수동 수정본 우선).
- 리마인드·미팅요청 단계 메시지는 기업 요약을 반복하지 않고 **오프닝(짧은 재인사) + 클로징만** 전송(기본값, 템플릿에서 조정 가능).
- 1건의 카톡 메시지로 전송(분할 없음). 조합 결과 3,000자 초과 시 경고(카톡 장문 붙여넣기 안정성).

### 입출력
- 입력: 회차·기업 선택, 오프닝/클로징 템플릿 CRUD, 대상 선택, 문안 오버라이드, 시퀀스 [응답 옴]/[중단].
- 출력: `deal_batches`(발송일·주기유형 포함), `send_jobs` + `send_items`(담당자별·단계별 최종 문안 스냅샷 — 발송 후 문구를 고쳐도 이력 불변), `send_sequences`(단계·다음 예약일·상태).

### 엣지케이스
| 케이스 | 처리 |
|---|---|
| 발송 도중 에이전트 연결 끊김 | 미발송 건 pending 유지, 재연결 시 이어서 발송(중복 발송 방지: sent 기록 기준) |
| 같은 담당자에게 같은 회차 중복 발송 시도 | 대상 선택 시 "이미 발송됨" 배지 + 기본 체크 해제 |
| 담당자 방 이름 미검증(○) | 대상 목록에서 경고 아이콘, 확인 모달에 별도 경고 섹션 |
| 발송 상한 초과(1회차 60명 초과) | 경고 + 분할 발송 권고(계정 제재 리스크 고지, TECH_SPEC §8) |
| 야간 발송 | 21시~08시 [발송 시작] 시 확인 경고(수신자 경험 보호, 강제 차단은 안 함) |
| 관리자 열람 | 회차 원문·인사문구는 관리자에게 비노출, 발송 건수만 집계 |
| 후속 도래일에 사용자가 미접속 | 시퀀스는 due 상태로 대기(자동 발송 안 함), 다음 접속 시 "밀린 후속 N건" 배너. 3일 이상 밀리면 다음 단계 예약일도 순연 |
| 시퀀스 진행 중 같은 담당자에게 새 회차 발송 | 기존 시퀀스 자동 중단(superseded) 후 새 시퀀스 시작 |
| [응답 옴] 실수 클릭 | 시퀀스 상태 되돌리기 허용(중단 후 24시간 내 [재개]) |
| 리마인드 예약일이 공휴일/주말 | 다음 영업일로 이월(창 범위 내 우선) |

## 6. 화면 6 — 팀 현황 (admin-dash, 관리자 전용)

**목적**: 사용자별 활동을 **집계 수치로만** 열람하고 주간 보고를 내보낸다.

### 화면 구성
- 기간 선택(이번 주/지난 주/월). 
- 사용자별 표: 이름 / 연결 투자사 수 / 딜소개 발송 수(성공 기준) / 홍보 메일 건수 / IR 처리 건수 / 미팅 수 / 주간 목표 달성률(%).
- 팀 합계 행 + 추이 미니 차트(주별 발송 수).
- [주간 보고 내보내기]: CSV/Markdown 다운로드.

### 권한 규칙 (확정)
- 관리자는 **집계만**: 개인 체크리스트 원문, 딜소개·IR 발송 원문, 인사문구, 담당자 메모에 접근하는 API 자체가 role=admin에 대해 403.
- 관리자 계정은 사용자 겸직 불가(별도 계정). 계정 생성·삭제(퇴사 처리)는 관리자 권한.

### 엣지케이스
- 삭제(퇴사)된 사용자: 과거 주간 집계에 "퇴사자(익명)"으로 합산 유지, 개인 식별 정보는 제거.
- 데이터 없는 신규 사용자: 0으로 표시(오류 아님).

## 7. 자동화 상세 기획 (6개)

> 실현 방법 판정·기술 구조는 TECH_SPEC이 최종 근거. 여기서는 기능 관점 명세만 정리한다.
> **확정: 카카오 발송(#1, #2)은 Windows 데스크톱 카카오톡 UI 자동화(발송 에이전트)로 구현한다. 공식 API는 미채택.**

### #1 카톡 딜소개 자동 발송 + 후속 캐던스 (P0)
- 범위: 단발 발송이 아니라 **Day1 딜소개 → Day6~7 리마인드 → Day11~14 미팅요청**의 3단계 시퀀스 자동 관리(§5 캐던스). 응답/IR 요청/미팅 발생 시 시퀀스 자동 중단.
- 트리거: Day1은 딜소개 보내기 [발송 시작], 후속 단계는 스케줄러가 도래분을 대기 목록으로 만들고 사용자가 [후속 발송 시작] (수동 트리거만 — 무인 발송은 하지 않음, 리스크 §8).
- 입력: `send_items[]` (방 이름, 단계, 최종 문안 스냅샷 — 오프닝(첫연락/재연락 자동 선택) + 자동 생성 기업 요약 + 단계별 클로징).
- 처리: 에이전트가 카톡 창 활성화 → 방 검색·열기 → 문안 클립보드 붙여넣기 → Enter 전송 → 방 닫기 → 랜덤 지연(3~7초) → 다음 건.
- 출력: 건별 sent/failed(+단계·시각) + 실패 사유 + 실패 시 스크린샷 경로. 성공 시 담당자의 '최근 딜소개' 갱신, Day1 성공 시 `send_sequences` 생성·다음 단계 예약.
- 재시도: 실패 건 자동 1회 재시도(말미에), 이후 수동 [재시도]. 단계 실패가 지속되면 시퀀스는 해당 단계에서 대기(다음 단계로 건너뛰지 않음).
- 정기 회차: 매월 첫째·셋째 수요일 회차 초안 자동 생성(schedule_rules 설정 기반, 2026-09 시행).

### #2 IR 요청 자동 응대 — IR 드라이브 링크 포함 메시지 자동 발송 (P0)
- **확정**: 카톡 파일 첨부 자동화는 하지 않는다. IR 자료는 구글 드라이브 링크로 관리하고 메시지 본문에 링크를 포함해 **텍스트 전송만** 자동화한다(#1과 동일 메커니즘 재사용 → 에이전트 단순·안정).
- 트리거: IR·미팅 관리 [IR 전달].
- 입력: 안내 문구(IR 현황·딜소개 문구·보고서 요약 자동 생성 + 수정), 기업의 `ir_drive_url`(본문 자동 삽입), 대상 방 이름.
- 처리: 링크 포함 최종 문안을 send_item으로 큐잉 → 에이전트가 #1과 동일하게 텍스트 전송.
- 출력: `ir_requests.status → 전달완료`, 전달 시각, 건별 로그.
- 실패 처리: 실패 시 미전달 유지 + [재시도]. 링크 미등록 기업은 큐 추가 전에 등록 유도(§2 엣지케이스).

### #3 항목별 필터 드롭다운 (P1) — 공통 컴포넌트 명세 (§8)

### #4 투자사 시트 한 페이지 표시 (P1) — §3의 7컬럼 고정 레이아웃 명세로 구현.

### #5 미팅 후 10일 경과 알림 (P2 — 발송 채널 결정 보류)
- **발생 조건·스케줄·대상 산출 로직은 정상 설계**: `meetings.status = 완료` 전환 시 완료일+10일 09:30에 `notifications` 레코드 예약(기산 일수는 schedule_rules `followup_after_meeting_days`). 미팅 상태가 완료 외로 바뀌거나 '다음 액션 완료' 체크 시 예약 자동 취소.
- **발송 채널은 미정(SMS vs 카톡, 사용자 고민 중 → 보류)**. 구현은 `NotificationChannel` 어댑터 인터페이스로 추상화(TECH_SPEC §6): `InAppChannel`(MVP 기본) / `SmsChannel`(CoolSMS 등) / `KakaoChannel`(에이전트 경유) — 나중에 결정되면 어댑터만 끼운다.
- **MVP 동작**: 도래한 알림을 앱 내 배너 + 오늘 할 일 항목("△△ 미팅 후 10일 경과 — 후속 연락")으로 표시. 외부 발송 없음.
- 문안(공통): "[dealflow] {투자사} {담당자명} 미팅({기업명}) 후 10일 경과. 후속 연락을 진행하세요."
- 발송/표시 이력은 `notifications`에 기록.

### #6 휴대폰 번호 로그인 + 퇴사 삭제 (P1)
- 로그인: 휴대폰 번호 입력 → SMS 인증번호 6자리(5분 유효, 5회 실패 시 10분 잠금) → 세션 쿠키 발급(14일).
- 최초 계정은 관리자가 번호 사전 등록(화이트리스트) — 등록 안 된 번호는 로그인 불가.
- 퇴사 처리: 관리자 팀 현황 → 사용자 [삭제] → 2단계 확인 → 개인 데이터 하드 삭제 + 집계 익명화(상세 TECH_SPEC §7).
- 엣지케이스: SMS 미도착 → 60초 후 재전송 허용(일 10회 상한). 번호 변경 → 관리자만 수정 가능.

## 8. 공통 컴포넌트 — 컬럼 필터 드롭다운 명세 (자동화 #3)

적용 화면: 내 투자사, 딜 기업 DB, IR·미팅 관리(두 표), 팀 현황.

### 동작
- 각 필터 대상 컬럼 헤더에 ▾ 버튼 → 드롭다운 패널:
  - 해당 컬럼의 **고유값 목록 + 건수** (예: `Seed (12)`, `Series A (8)`) 체크박스 다중 선택.
  - 상단 검색 입력(고유값 10개 초과 시), [모두 선택] [해제].
- 복수 컬럼 필터는 **AND** 결합, 같은 컬럼 내 다중 선택은 **OR**.
- 활성 필터는 표 상단에 **칩**으로 표시(`단계: Seed, A ✕`), ✕로 개별 해제, [필터 초기화].
- 필터 상태는 URL 쿼리스트링에 반영(`?stage=seed,a&status=active`) → 새로고침·공유 시 유지.
- 구현: 데이터 규모(수백 행)상 **클라이언트 사이드 필터링**(vanilla JS, 서버는 전체 목록 렌더). 1,000행 초과 시 서버 필터로 전환하는 기준만 코드 주석으로 남긴다.

### 엣지케이스
- 빈 값: "(비어 있음)" 항목으로 필터 가능.
- 필터 결과 0건: "조건에 맞는 항목이 없습니다" + [필터 초기화] 버튼.
- 다중 값 셀(섹터 태그 등): 태그 단위로 고유값 분해, 하나라도 일치하면 표시.
