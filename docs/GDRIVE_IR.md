# 구글 드라이브 IR 수신 확인 — 준비하기 (#155)

IR 자료가 올라오는 **구글 드라이브 폴더**를 서버가 30분마다 읽어, PDF · PPT 파일 이름에서 기업을 찾으면
그 기업의 **`IR 자료 수신`** 칸(IR 기업 현황 · Series A 이상 딜 소싱 두 탭)에
`2026/11/04 수신완료 (드라이브: 파일이름)` 을 저절로 적습니다.
사람이나 Claude 가 없어도 서버 혼자 돕니다. 코드는 `app/services/gdrive_ir.py` 입니다.

준비는 사람이 한 번 합니다. 아래 순서대로 하면 됩니다. **준비가 안 되어 있으면 이 기능은 조용히
꺼져 있고 앱은 평소대로 돕니다** — 팀 현황 판에 `설정 없음` 이라고만 보입니다.

> 이 문서와 저장소에는 진짜 키 · 폴더 id 를 적지 않습니다(저장소가 공개입니다).
> 아래의 `xxxx` · `예시` 값은 모두 가짜입니다.

---

## 1. 구글 클라우드에서 서비스 계정 만들기

서비스 계정은 **사람이 아닌 서버용 구글 계정**입니다. 이 계정에게 IR 폴더만 '보기'로 열어 줍니다.

1. <https://console.cloud.google.com> 에 IR 폴더를 관리하는 구글 계정으로 들어갑니다.
2. 위쪽 프로젝트 고르기 › **새 프로젝트** — 이름 예: `dealflow-drive`. (이미 쓰는 프로젝트가 있으면 그걸 써도 됩니다.)
3. 왼쪽 메뉴 › **API 및 서비스 › 라이브러리** › `Google Drive API` 검색 › **사용** 을 누릅니다.
4. 왼쪽 메뉴 › **IAM 및 관리자 › 서비스 계정** › **서비스 계정 만들기**
   - 이름 예: `dealflow-drive-reader`
   - **역할(권한) 고르는 단계는 건너뜁니다** — 프로젝트 권한은 필요 없습니다. 폴더 공유만으로 읽습니다.
5. 만든 서비스 계정을 눌러 **키 › 키 추가 › 새 키 만들기 › JSON** 을 고릅니다. JSON 파일 하나가 내려받아집니다.
   - **이 파일은 비밀번호와 같습니다.** 카톡 · 메일 · 저장소 · 공유 드라이브에 올리지 마세요.
   - 키 만들기가 '조직 정책' 때문에 막혀 있으면 — 설정할 때 확인이 필요합니다(멈추고 알려 주세요).
6. 서비스 계정의 **이메일 주소**(`…@….iam.gserviceaccount.com`)를 복사해 둡니다. 다음 단계에서 씁니다.

## 2. `IR Deck` 폴더를 서비스 계정에 '보기'로 공유하기

**넣을 폴더는 `IR Deck` 하나입니다**(11/04 결정). 그 안의 하위 폴더 `_기타` 도 함께 읽힙니다 —
하위 폴더는 따로 공유하지 않아도 위 폴더를 따라갑니다. 다른 IR 관련 폴더는 넣지 않습니다.
(코드는 쉼표로 여러 폴더를 받을 수 있지만, 지금은 하나만 씁니다.)

`IR Deck` 은 **공유 드라이브** 안에 있습니다. 서비스 계정 주소(`…iam.gserviceaccount.com`)는 회사 밖
계정으로 치므로, 공유 드라이브가 바깥 계정을 막아 두었으면 공유가 안 됩니다. 아래 순서로 확인합니다.

1. **바깥 계정을 넣을 수 있는지 먼저 확인** — 공유 드라이브 이름 옆 ▾ › **공유 드라이브 설정** 을 엽니다.
   - `조직 외부 사용자 액세스 허용`(또는 `회사 외부 사용자가 이 공유 드라이브의 파일에 액세스하도록 허용`)이
     **켜져 있으면** 다음 2 로 갑니다.
   - **꺼져 있으면** 그 항목을 켭니다(그 공유 드라이브의 관리자만 바꿀 수 있습니다). 회사 관리 콘솔이 막아
     두어 못 켜면 — 설정할 때 확인이 필요합니다(멈추고 알려 주세요).
2. 드라이브에서 `IR Deck` 폴더를 오른쪽 클릭 › **공유** › 1-6 에서 복사한 서비스 계정 이메일을 넣고 권한은
   **뷰어(보기)** 로 둡니다. '알림 보내기'는 꺼도 됩니다. — **폴더에 직접 공유하는 이 방법을 먼저 씁니다**
   (서비스 계정이 그 폴더만 봅니다).
3. 폴더 공유 창이 "외부 사용자와 공유할 수 없음" 이라고 막으면 대안 둘:
   - 1 의 `조직 외부 사용자 액세스 허용` 을 켠 뒤 2 를 다시 합니다.
   - 또는 공유 드라이브 › **구성원 관리** 에서 서비스 계정을 **뷰어** 로 넣습니다(이 경우 그 공유 드라이브의
     다른 폴더도 읽을 수 있게 되지만, 서버는 아래 3장에 넣은 폴더만 읽습니다).
4. 6장에서 켠 뒤 판에 `IR Deck` 과 **접근 성공** 이 보이면 공유가 된 것입니다.
   `권한 없음` · `폴더를 찾지 못했습니다` 가 보이면 2~3 을 다시 봅니다.

## 3. 폴더 id 찾기

`IR Deck` 폴더를 열면 주소가 `https://drive.google.com/drive/folders/xxxxxxxxxxxxxxxx` 꼴입니다.
`folders/` 뒤의 글자가 폴더 id 입니다 — **이 하나**를 5장에 넣습니다. 주소를 통째로 넣어도 서버가 id 를
꺼내 씁니다. (`_기타` 같은 하위 폴더 id 는 넣지 않습니다.)

## 4. 서버에 키 파일 두기

키는 **서버의 데이터 폴더 안 `secrets` 폴더**에 둡니다. 이 폴더는 컨테이너 안에서
`/app/data/secrets/` 로 보입니다. 저장소 폴더(`~/…/app`)에는 두지 마세요 — 빌드할 때 이미지에
들어갈 수 있습니다(안전망으로 `.dockerignore` · `.gitignore` 가 `secrets/` · `gdrive-sa*.json` 을 막아 둡니다).

```bash
# 내 PC 에서 — 내려받은 키를 서버로 옮긴다(파일 이름은 예시)
scp -i <서버 접속 키> ~/Downloads/dealflow-drive-xxxx.json ubuntu@<서버 주소>:/tmp/gdrive-sa.json

# 서버에서 — 데이터 폴더 아래 secrets 로 옮기고 나만 읽게 한다
sudo mkdir -p /home/dealflow/data/secrets
sudo mv /tmp/gdrive-sa.json /home/dealflow/data/secrets/gdrive-sa.json
sudo chmod 600 /home/dealflow/data/secrets/gdrive-sa.json
```

- `deploy/.env` 에서 `DEALFLOW_DATA_DIR` 를 바꿔 썼다면 `/home/dealflow/data` 대신 그 경로입니다.
- 앱의 일일 백업은 `*.db` 파일만 뜨므로 키는 백업에 안 들어갑니다. **NAS 백업이 데이터 폴더를
  통째로 가져간다면 키도 함께 갑니다** — 설정할 때 확인하세요.
- 내 PC 의 내려받은 키 파일은 서버에 옮긴 뒤 지웁니다.

## 5. 서버 `deploy/.env` 에 두 줄 넣기

```bash
# 컨테이너 안에서 본 키 파일 경로
DEALFLOW_GDRIVE_SA_FILE=/app/data/secrets/gdrive-sa.json
# IR Deck 폴더 id 하나 (코드는 쉼표로 여럿을 받지만 지금은 하나)
DEALFLOW_GDRIVE_FOLDER_ID=xxxxxxxxxxxxxxxx
```

`.env` 를 고친 뒤에는 컨테이너를 다시 만들어야 읽힙니다(다음 배포 때 함께 되어도 됩니다).

```bash
cd /home/dealflow/app/deploy && docker compose -f docker-compose.prod.yml up -d --force-recreate web
```

## 6. 켜기 — 팀 현황 › `자동화 · 구글 드라이브 IR 수신 확인`

1. 판에서 **키: 있음**, **폴더: N개** 가 보이는지 봅니다.
2. **처음 확인 때 이미 있던 파일도 적기** 를 정합니다.
   - 켜 두면(기본) 폴더에 이미 있는 IR 파일들도 그 기업 칸에 적습니다(각 파일이 올라온 날짜로).
   - 끄면 지금 있는 파일은 본 것으로만 두고, **켠 뒤에 올라오는 파일만** 적습니다.
3. **켜기 › 켜짐** 으로 저장합니다. 5분 안에 첫 확인을 합니다.
4. 판에 폴더 이름과 **접근 성공** 이 보이면 끝입니다. **접근 실패** 면 그 옆의 까닭(공유 · 폴더 id)을 고칩니다.

## 판에서 보이는 것

| 칸 | 뜻 |
|---|---|
| 상태 | 설정 없음 / 꺼짐 / 켜짐 — N분마다 확인 · 마지막 확인 · 다음 확인 |
| 키 | 있음 / 없음(환경변수 없음 · 그 경로에 파일 없음). 키 내용 · 경로는 보이지 않습니다 |
| 폴더 | 넣은 폴더 수, 폴더마다 접근 성공/실패와 까닭, 하위 폴더 수 |
| 적은 수 | 지금까지 `IR 자료 수신` 칸에 적은 수 |
| 확인 필요 | 기업을 못 찾았거나(0곳) 여러 곳이라 적지 않은 파일 — 파일 이름(드라이브 링크) · 까닭 · 후보 기업 |
| 최근 처리 | 최근 적은 파일, **건너뛴** 파일(그 기업 칸에 이미 값이 있었음), **건너뜀 (파일 종류)** 파일(PDF · PPT 가 아님) — 두 탭 중 어느 줄에 적었는지도 |
| 파일 종류로 건너뜀 | PDF · PPT 가 아니라 적지 않은 파일 수(확인 필요에는 안 올립니다) |

`확인 필요` 파일은 사람이 그 기업 줄의 `IR 자료 수신` 칸에 손으로 적어 주세요. 그 기업이 나중에 IR 기업
현황에 들어오거나 이름이 고쳐지면 다음 확인 때 저절로 적힙니다.

## 규칙 (요약)

- **PDF · PPT 만** 봅니다 — 확장자 `pdf` · `ppt` · `pptx` · `key`, 또는 그 종류의 파일(mimeType). 구글 슬라이드도
  듭니다(PPT 와 같은 발표 자료인데 확장자가 없어 종류로만 알아봅니다). 그 밖의 파일(docx · xlsx · 그림 등)은
  `건너뜀 (파일 종류)` 으로 기록만 하고 `확인 필요` 에는 올리지 않습니다.
- **기업이 정확히 하나로 정해질 때만** 적습니다. 대상은 IR 기업 현황 + Series A 이상 딜 소싱 기업입니다.
- **두 탭 모두 적습니다** — IR 기업 현황 줄과, 그 기업에 이어진(또는 같은 이름의) Series A 이상 딜 소싱 줄.
- 법인 표기((주) · 주식회사 · ㈜), `TalkFile_` 같은 앞머리, 날짜 · 버전 · `IR` · `deck` 같은 꼬리,
  띄어쓰기, 대소문자, 맥에서 올린 한글 자모 차이는 무시합니다. 낱말 한가운데는 맞추지 않습니다
  (`가나` 가 `가나다라전자` 에 맞지 않습니다).
- 이름 끝의 꼬리표(`[딜소개 불가/…]`)는 떼고 봅니다. 떼고 나서 이름이 겹치는 기업이 둘이면 '확인 필요' 입니다.
- 파일 이름에서 못 찾으면 그 파일이 든 **하위 폴더 이름**으로 한 번 더 찾습니다(기업마다 폴더를 둔 경우).
- **이미 값이 있는 칸은 덮지 않습니다** — 줄마다 따로 봅니다(IR 줄에 값이 있어도 Series A 줄이 비어 있으면
  Series A 줄에는 적습니다). 같은 기업에 파일이 또 오면 건너뛰고 기록만 남깁니다.
- **`IR 자료` 칸(발송 PC 가 붙일 파일 이름)에는 쓰지 않습니다.**
- 수정 기록에는 주체 **자동** 으로 남습니다. 드라이브에는 읽기만 합니다.

## 비용

**돈이 드는 구글 서비스는 쓰지 않습니다.** 푸시 알림(Pub/Sub · watch 채널), Cloud Functions,
Cloud Storage, Cloud Run 을 쓰지 않고 **Drive API 읽기와 서비스 계정**만 씁니다.

### 하루 호출 수 (기본값: 30분 간격, 폴더 20개 이하)

| 무엇 | 하루 | 근거 |
|---|---|---|
| 평소 확인 | 약 47건 | 30분마다 1회 = 하루 48회. 한 회차는 알고 있는 폴더 전부(20개씩 묶음)를 **한 번에** 묻고, 지난 확인 뒤 **생기거나 바뀐 파일만**, 필요한 칸만 받습니다. 폴더 트리는 기억해 두고 다시 훑지 않습니다. |
| 하루 한 번 전체 대조 | 약 3~5건 | 폴더마다 접근 확인 1건 + 폴더 깊이마다 목록 1건. 시각으로 못 잡는 파일(다른 곳에서 옮겨 온 파일 · 이름만 바꾼 파일)과 지운 파일을 맞춥니다. |
| **합계 (Drive API)** | **약 50건** | 폴더 3개 · 하위 폴더 1단이면 47 + 5 ≈ 52건 |
| 토큰 받기 | 약 24건 | 키로 받는 출입증이 1시간 가므로 시간당 1번. 인증 서버 호출이라 Drive API 할당량에 들지 않습니다. |

파일이 1,000개를 넘는 폴더 묶음은 쪽마다 1건이 더 듭니다. 간격을 60분으로 늘리면 절반이 됩니다.

### 사용료 · 할당량

- **Drive API 는 사용료가 없습니다 — 할당량만 있습니다.** 기본 할당량은 분당 수천 건 단위라
  하루 50여 건은 그 한참 아래입니다. 정확한 숫자는 콘솔 › API 및 서비스 › Google Drive API › 할당량에서 볼 수 있습니다.
- **결제 계정(카드)**: Drive API 를 켜고 서비스 계정을 만드는 데에는 결제 계정이 필요 없는 것으로
  알고 있습니다. 다만 확실하지 않으니 **설정할 때 확인**하세요 — 콘솔이 결제 계정 연결을 요구하면
  진행하지 말고 알려 주세요.
- 할당량을 넘으면 판에 `할당량 초과` 가 뜨고 다음 회차에 다시 합니다. 앱은 멈추지 않습니다.

### 서버(OCI) 부담

거의 없습니다. 30분마다 작은 HTTPS 요청 한 번(응답은 필요한 칸만 담은 작은 JSON)이고, 새 컨테이너 ·
새 실(스레드) · 새 DB 표를 만들지 않습니다(자동화가 이미 5분마다 깨어나는 실에 얹혀 돕니다).
본 파일 목록은 DB 의 설정 줄 하나에 담기며 파일 수천 개여도 수백 KB 안쪽입니다.

## 키를 바꾸거나 끌 때

- **끄기**: 판에서 `꺼짐` 으로 저장합니다. 이미 적힌 값은 그대로 둡니다.
- **키 바꾸기**: 콘솔에서 새 키를 만들어 4장처럼 같은 경로에 덮어씁니다. 다음 확인부터 새 키를 씁니다.
  옛 키는 콘솔 › 서비스 계정 › 키 에서 지웁니다.
- **완전히 걷기**: 폴더 공유에서 서비스 계정을 빼고, `deploy/.env` 의 두 줄을 지우고, 서버의 키 파일을 지웁니다.

## 문제가 생기면 (판의 까닭 글)
